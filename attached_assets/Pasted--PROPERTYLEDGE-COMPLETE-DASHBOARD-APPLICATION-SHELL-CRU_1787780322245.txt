# PROPERTYLEDGE — COMPLETE DASHBOARD, APPLICATION SHELL, CRUD & UX REBUILD

## ROLE

You are a senior product designer, UX engineer, frontend architect, and full-stack engineer working directly inside the existing PropertyLedge codebase.

Your job is to redesign the authenticated PropertyLedge application so it feels like a **premium, modern, Apple-quality professional application**, while retaining the actual purpose of PropertyLedge:

> A powerful property-management workspace where users can manage properties, tenants, leases, payments, invoices, expenses, maintenance, inspections, documents, tasks, and related operational data.

This is NOT a request to create a static visual concept.

This is a request to **rebuild the actual working application UI/UX around the existing backend, data model, authentication, CRUD operations, AG Grid implementation, and routes.**

Every important workflow must remain functional.

---

# 1. PRIMARY DESIGN GOAL

The new PropertyLedge experience should feel:

* premium
* calm
* precise
* responsive
* modern
* highly polished
* fast
* information-dense without feeling cluttered
* professional enough for serious property managers
* simple enough that a new user understands what to do immediately

The interaction quality should be inspired by the principles of Apple's software:

* excellent spacing
* clear hierarchy
* subtle animations
* smooth transitions
* contextual actions
* progressive disclosure
* minimal visual noise
* excellent forms
* immediate feedback
* strong typography
* carefully controlled color
* predictable navigation
* responsive interaction
* polished empty/loading/error states

DO NOT simply copy Apple's visual design.

PropertyLedge must still look like PropertyLedge.

The design language should be:

> **Apple-quality interaction design + professional property-management information density.**

# 4. CRITICAL RULE — FUNCTIONALITY FIRST

Do not sacrifice working functionality for visual design.

Every redesign must preserve existing functionality.

If an existing button currently creates a property, the redesigned button must still create a property.

If an existing row opens a detail page, the redesigned row must still open the detail page.

If an existing edit action opens an edit form, the redesigned edit action must still edit the actual database record.

If delete currently works, delete must continue to work.

If filtering works, filtering must continue to work.

If sorting works, sorting must continue to work.

If permissions exist, permissions must remain enforced.

DO NOT replace working CRUD with:

* mock data
* fake dialogs
* placeholder handlers
* console.log
* temporary arrays
* frontend-only state
* hardcoded success messages

The UI must connect to the actual application logic.

# 77. CORE UX PHILOSOPHY

Build every screen around these principles:

### 1. Context when needed.

Show:

* breadcrumb
* title
* description
* explanation

when the user arrives.

### 2. Workspace when working.

As the user works:

* reduce chrome
* reduce spacing
* maximize data

### 3. Preserve context.

Forms and drawers should not unnecessarily eject users from their workspace.

### 4. Make actions obvious.

Primary action should always be clear.

### 5. Make destructive actions deliberate.

Never make deletion accidental.

### 6. Give immediate feedback.

Every meaningful action should communicate its state.

### 7. Don't invent data.

Everything important should be based on the actual PropertyLedge backend.

### 8. Don't break functionality for aesthetics.

Working CRUD always wins.
